## 1. PRD 8절 "미결정 사항" — 코드 기준 확정

| 질문 | 확정된 사실 (근거) |
|---|---|
| **어떤 임베딩 모델/버전을 쓰는가** | **경로가 둘로 갈려 있고 서로 다른 모델을 쓴다.** ① 배치 파이썬 경로: `BAAI/bge-m3` (기본, `common.py:37`, `.env.example:11`). ② 웹 경로: `Xenova/multilingual-e5-small` (384차원 경량, `web/index.html:368`). **두 경로의 검색 결과가 서로 다르다** — 데모(웹)에서 본 품질과 배치 품질이 다를 수 있음. |
| **청킹은 어떤 기준인가** | 문자 수 기준 고정 길이 + 문단/문장 경계 우선. `CHUNK_SIZE=1200자`, `CHUNK_OVERLAP=200자` (`common.py:50-51`, `chunk_text` `common.py:159-183`). **토큰이 아니라 문자 기준**. 웹은 동일 로직이나 **기본이 "쪼개지 않음(문서 1개=벡터 1개)"** (`web/index.html:110`, 체크박스 기본 해제). |

| **목표 응답 속도·동시 사용자 규모** | 코드/설정 어디에도 명시 없음. **여전히 미결정** — PRD에서 확정 필요. |

## 2. 원인 가설 대조 (PRD 2.3 → 코드 근거)

### 가설 1. 청킹 전략 문제 — **부분 확정 (웹은 심각)**
- 배치 경로: 1200자/200자 overlap, 문단 경계 우선. 데모 규모엔 무난하나 **토큰 상한이 아니라 문자 상한**이라 모델 최대 입력과 어긋날 수 있음.
- 웹 경로: **기본값이 "문서 통째로 임베딩"** (`splitChunks` 체크박스 기본 해제, `web/index.html:110`, `445`). 한 문서를 벡터 1개로 만들면 여러 주제가 한 벡터에 평균돼 **"뭉개짐"** → PRD가 지목한 *"유사도 변별력 부족"* 의 직접 원인. 최근 커밋(`8f045b0`, `a4859d2`)이 이 모드를 넣고, 낮은 변별력을 "관련도 %" 보정으로 덮으려 한 흔적이 보임.
- **결론: 웹 기본값을 "쪼개서 임베딩"으로 되돌리는 것이 가장 값싸고 효과 큰 수정.**

### 가설 2. 임베딩 모델 – 도메인/언어 불일치 — **부분 확정**
- 배치는 `bge-m3`(한국어 강함) 로 합리적 선택. 다만 **웹은 `multilingual-e5-small`(384d)** 로 훨씬 약함. 감사 도메인 전문용어에서 e5-small 은 유사도가 좁은 고범위(예 0.75~0.9)에 몰리는 경향 → 변별력 저하로 보임.
- e5 계열은 `query:`/`passage:` 프리픽스가 **필수**인데, 배치는 `.env` 로 켜야 하고 기본은 비어 있음(`common.py:46-47`). 웹은 프리픽스를 항상 붙여(`web/index.html:380`) 올바름. **배치에서 e5 로 바꿀 때 프리픽스를 빼먹으면 성능이 크게 떨어지는 함정 존재.**
- 실제 모델 후보 비교(3단계)는 재임베딩 비용 때문에 별도 단계로 남김. 여기선 **버그부터** 잡는다.

### 가설 3. 검색 로직 미완성 (하이브리드 부재) — **확정**
- `search.py` 는 순수 dense 검색뿐(`vectors @ qvec`, `search.py:61`). BM25 등 키워드 결합 없음.
- 감사 데이터는 `제74조제5항`, `㈜케이티`, `990,323원`, `일상감사시행세칙` 처럼 **정확 일치가 중요한 고유표현**이 핵심(샘플에서 실제 확인). 순수 임베딩은 이런 토큰의 정확 매칭에 약함 → **하이브리드 검색이 정확도에 가장 직접적.**

### 가설 4. 전처리 누락 — **부분 확정**
- `_tidy`(`extract.py:225`)는 공백만 정리. **반복되는 머리말/꼬리말·페이지번호·목차 점선 등 노이즈 제거 로직 없음.**
- PDF 추출이 `page.get_text()`(배치) / 항목을 공백으로 이어 붙임(웹, `web/index.html:203`) → 표·다단 레이아웃에서 **어절이 잘못 붙거나 깨질 수 있음**. 샘플 성과감사 PDF 에서 `오신청사항이발견되어` 처럼 공백 소실 확인.
- 스캔 PDF(`2023_감사보고서_스캔본.pdf`)는 추출 텍스트 0 → 자동 skip(정상 동작 확인). OCR 은 옵션.

### 가설 5. 정규화/거리 계산 — **대체로 정상, 단 풀링 버그 있음**
- L2 정규화 후 내적 = 코사인. 구현 정확(`common.py:154-156`, `embed.py`, `search.py:61`). **거리계산·정규화 버그는 없음.**
- 그러나 **bge-m3 를 hf_api 로 쓸 때 토큰 단위 출력(n_tokens, dim)을 mean-pooling**(`common.py:126-127`). bge-m3 의 공식 dense 임베딩은 **CLS 토큰**(첫 토큰) 기반이라, mean-pooling 은 다른(열화된) 표현을 만든다 → 낮고 뭉툭한 유사도의 원인 중 하나. **로컬 backend(`sentence-transformers`)는 모델 고유 풀링을 써서 정상**이므로, 이 버그는 hf_api 경로 한정.

### 가설 6. Reranking 부재 — **확정**
- 1차 결과를 재정렬하는 cross-encoder 등 단계 없음. 이번엔 **훅(구조)만** 마련하고 실제 rerank 모델 연동은 후속(4단계 후반).

### 추가 관찰 H — "관련도 %" 보정은 임시방편
- `runSearch`(`web/index.html:500-530`)가 전체 문서 점수의 **median 을 기준선**으로 빼서 %를 만든다. 표본이 3건 미만이면 `0.75` 상수로 대체. **문서가 몇 건뿐이면 median 이 불안정**해 %가 왜곡됨. 근본 변별력(가설 1·2·3)을 고치지 않고 표시만 조정하는 방식이라 **오해를 부를 수 있음**(관련 있는데 0%로, 혹은 반대로). 유지하되, 실제 개선은 검색 품질 자체에서 나와야 함.

## 3. 8만 건 규모 확장성 경고 (현 구조 기준)

- `index.npz` 단일 파일 + 전량 로드 + 브루트포스 내적. 8만 청크 × 1024차원(bge-m3) × float32 ≈ **320MB 벡터**를 매번 메모리에 올리고 전수 계산. 검색 자체는 수백 ms~수 초 가능하나, **메모리 상주·콜드 로드·동시성**에서 병목.
- 권장(후속 4단계): **pgvector + HNSW** 또는 FAISS 로 ANN 인덱스화. 본 변경 범위 밖(별도 저장소 필요)이라 여기서는 다루지 않되, PRD 8절 "저장소 확정"의 결정을 촉구.

## 5. 후속 결정 반영 (사용자 방향 확정: 파이썬 + 한국어 특화 모델)

초기 웹 데모(e5-small)의 낮은 의미 변별력을 후처리 heuristic(코사인 보정·키워드 커버리지)으로
덮으려 했으나, **경량 모델의 의미 이해 한계는 후처리로 해결되지 않는다**는 점을 확인. 방향을
아래로 확정하고 반영했다.

- **모델(3단계 확정)**: 기본 경로를 **로컬 `sentence-transformers` + `nlpai-lab/KURE-v1`
  (한국어 특화, bge-m3 파인튜닝)** 로 전환. `.env` 기본값 `EMBEDDING_BACKEND=local`,
  `EMBEDDING_MODEL=nlpai-lab/KURE-v1`, 토큰 불필요. 로컬 백엔드는 모델 고유 풀링을 써서
  hf_api 의 풀링 이슈(B)에서도 자유롭다.
- **관련성 게이트(신규)**: 결과 노출 여부를 **순수 의미(dense 코사인) 기준**으로 결정
  (`MIN_RELEVANCE`, 기본 0.5). 키워드만 겹치는 무관 문서는 순위에 오르더라도 **표시하지 않음**.
  관련 문서가 없으면 "관련 문서 없음"을 명시. → 증상 "관련 없는 문서가 관련도 70%" 해결.
- **하이브리드 비중**: 강한 한국어 모델에선 의미가 주도하도록 `HYBRID_ALPHA` 기본 0.6→0.75.
  키워드(BM25)는 정확 일치 보조로만.
- **웹 데모**: 경량 모델 한계를 명시하고, `SHOW_MIN`(관련도 25%) 미만 결과를 숨김 +
  정밀 검색은 파이썬 경로로 안내.

남은 후속: 실제 8만 건에서 KURE-v1 임베딩 시간/자원 측정, `MIN_RELEVANCE` 실측 튜닝,
pgvector/ANN 이관, 평가셋 확장(감사실 업무자 정답 라벨링).
